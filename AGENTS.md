# WorkingOut development

WorkingOut is Dion's native iOS fitness app for strength training and running. The four tabs are Overview, Training, Progress, and Profile. Develop only in DionBP/WorkingOut.

- Keep deterministic training models, canonical units, metrics, and reconciliation in `Packages/WorkingOutKit`. Use SwiftUI for presentation, `GymLog` for app persistence, and the Health and location adapters for platform services. Prefer Apple frameworks.
- Use native controls, semantic typography, adaptable layouts, and the shared TrainingDesign components. Maintain the dumbbell identity, charcoal base, and restrained lime accent. Check Dynamic Type, VoiceOver, light and dark appearances, and narrow devices.
- Add explicit English and Danish entries to `iOS/PadelApp/WorkingOut.xcstrings` for all new iPhone UI, errors, notifications and accessibility. Use `WorkingOutLanguage` and preserve the independently configured regional locale for formatting. Platform permission prompts, Watch and widgets use system language and their target catalogs.
- Persist stable IDs for exercises, workouts and programs. Preserve user names, notes and other original text. Keep kilograms, meters and seconds in storage and apply unit conversions at the presentation boundary.
- Keep local data usable without HealthKit. Ask for access from a screen with context. Treat absent read results as unknown, and preserve source and external identifiers. Deduplicate known exports using IDs and owned sync metadata. Garmin data arrives through Garmin Connect and Apple Health pending approved direct access.
- Treat training and GPS data as private. Store it locally with file protection and write snapshots atomically. Maintain backward-compatible decoders and migration fixtures. Preserve files when a read or migration fails. Keep legacy SwiftData schemas intact until their migration has been tested. External transfer requires a legitimate documented purpose and explicit consent.
- Put business rules in independently testable value types. Cover migration, recovery, validation, and units with Swift package tests. Run the localization checker and both package suites. Device features require physical iPhone checks for HealthKit, Garmin, GPS, notifications and permissions.
- Use a feature branch, focused commits and a PR. Existing GitHub Actions CI must use the xcode-27 runner, Xcode 27 and iOS 27 SDK. Verify actual results and fix failures before merging. Main triggers TestFlight.
- Preserve bundle IDs, schemes required by CI, icons, entitlements, App Store Connect configuration, deployment credentials and GitHub settings. Preserve certificate snapshotting, ownership verification, cleanup after failures, and safety tests. Revoke only verified temporary development certificates created for the current run. Never revoke distribution or other builds' certificates. Keep credentials and personal data out of logs.
- Done means the normal user workflow works, both translations are present, migration and package tests pass, the required Apple targets compile, and the README identifies material gaps and device checks.
